# 强 AI 训练路线

## 为什么不能直接“算出最优解”

正式 1v1 同时包含隐藏手牌、随机抽牌、随机效果、反制窗口、长时装备与状态、数千种
模组组合。它是大型部分可观测随机博弈，不适合穷举整棵游戏树。可行目标是通过自我
对局和真实数据逐步逼近强策略，并用固定擂台持续验证。

## 阶段 0：已完成的可执行基线

- 生产引擎环境和无泄漏信息集
- 完整战斗动作空间
- 4096 个官方模组请求组合验证
- 随机与启发式对手
- 并行自我对局和压缩轨迹
- 哈希线性动作价值基线
- 成对座位互换擂台、95% 置信区间、近似 Elo
- 轻量推理 sidecar 和规则指纹

线性基线的作用是尽早发现协议、数据和部署问题，不应作为最终 AI。

## 阶段 1：选牌与配装（协议已完成）

完整比赛协议现在已经包含：

1. 配装倾向和其子选择
2. 15 轮三选一、重抽和战斗动作

选牌模型能看到已选卡、下一牌类、候选三张、模组组合、配装和座位。所有候选继续由
生产引擎生成，因此污水首抽等特殊规则一致。下一步是把配装/选牌做成独立策略头，
先用真实选取率或高质量启发式行为克隆，再与战斗价值模型联合微调；当前哈希线性
基线暂时让同一动作打分器覆盖两个阶段。

## 阶段 2：序列策略（v1 已完成，结构化 v2 已打通）

当前已经实现一套可执行的 PyTorch 训练骨架：

- 哈希稀疏公开观测编码器
- 最近 32 项公开历史的 GRU 编码器
- 合法动作逐项编码和可变长度打分
- 预对局/战斗两个策略头与两个价值头
- 按对局稳定划分训练集和验证集的流式行为克隆
- 模型、特征、观测、动作和规则指纹的联合版本校验

动作数量会变化，因而应使用“观测编码 + 每个合法动作编码”的打分结构，不使用固定
几千维动作 softmax。当前模型只编码玩家真实可见的公开历史，不读取引擎隐藏状态。

这一阶段已经完成真实 XPU 训练、两轮联赛轨迹、严格 on-policy PPO 和成对擂台基准。
哈希 v1 的主要上限是把不同牌区、单牌、装备和玩家关系压入同一个特征袋。结构化 v2
已经将玩家、状态、装备、每张可见牌、区域、待选择项和公开历史拆成独立 token，使用
Transformer 编码状态，并让每个合法动作通过交叉注意力读取状态。未知的新牌名或状态
仍使用稳定哈希，不需要维护固定词表。

v2 首先通过 v8 教师蒸馏获得不低于现有策略的起点。缓存只需生成一次，包含教师完整
动作分布、价值、结构化稀疏张量、规则版本和教师逐张量指纹；调整训练轮次、优化器或
损失权重时不再解压 JSON 或重复执行教师网络。完成蒸馏后才进入大规模联赛 PPO 和搜索
教师阶段。后续仍应加入对手隐藏手牌与牌堆的 belief 表征，并研究可安全复用历史轨迹
的 V-trace/IMPALA 风格更新。

## 阶段 3：联赛式自我对局（基础版本已完成）

只让最新模型互打容易产生循环克制。维护以下对手池：

- 最新模型
- 历史强模型快照
- 启发式与随机基线
- 针对高使用率模组组合的专家模型
- 专门寻找漏洞的探索模型

按模组组合、先后手和花阶分段报告胜率。每次晋级至少做座位互换，并要求置信区间
下界超过当前线上模型，而不是只看单次胜率。

当前已经实现：

- 每局按权重随机抽取双方策略，支持历史模型、探索模型和启发式混合
- 神经策略温度采样与少量 epsilon 探索
- 同一工作进程只加载一次 checkpoint，后续对局共享只读权重
- 从历史 checkpoint 低学习率继续训练
- 胜、负、平决策使用不同策略损失权重
- 发生过循环恢复的整局默认不进入训练
- 多个候选通过随机模组组合和座位互换竞技场晋级
- 每个 PPO 决策记录行为策略的 log-prob、价值、熵和温度
- checkpoint 使用逐张量 SHA-256 指纹锁定轨迹来源，拒绝近似或错误版本的数据
- 同一批轨迹可让当前策略对镜像、历史冠军和启发式对手，训练时仅使用当前策略座位
- 裁剪策略损失、裁剪价值损失、全局 advantage 标准化、熵奖励和目标 KL 均已实现
- 支持按同一玩家的决策序列计算 GAE；`lambda=1` 精确退化为终局 Monte Carlo 优势

下一步不应继续无限堆行为克隆数据。更高收益方向是扩展多代对手池、增加按模组簇的
最差分位评估、训练 belief 表征，或由有限深度 rollout 产生改进动作标签。继续 PPO 时
应坚持新鲜轨迹、小学习率、单轮更新和独立留出竞技，避免在终局稀疏奖励上过拟合。
当前实测 `GAE lambda=0.95` 比所有动作共享同一终局回报更有效，但仍需用每轮新种子
验证，不能把单个成功超参数固化为普遍结论。

## 阶段 4：搜索增强（离线原型已完成）

在策略网络足够快后，可对少量关键决策做隐藏信息一致的搜索：

- 从 belief 中采样若干可能的对手手牌和牌堆
- 每个样本克隆生产引擎做有限深度 rollout
- 汇总合法动作的风险调整价值

不能使用真实隐藏状态直接搜索，否则离线得分很好、上线却属于作弊信息策略。

推荐先使用 v8 蒸馏后的结构化 v2，在策略概率最高的少量候选动作上做 1 至 2 回合的
短程 rollout。每个隐藏信息样本独立搜索并在最后汇总，搜索标签再蒸馏回无需搜索即可
部署的网络。达到对启发式 75% 不能作为唯一目标；还需同时通过历史冠军、模组最差
分位和真人诊断局，防止训练成只克制当前启发式规则的专用策略。

当前已经实现并验证：

- 每次 rollout 在克隆引擎中重新确定化对手隐藏手牌、抽牌堆、弃牌堆和放逐区
- 完整玩家可见观测必须与根状态逐值相同，否则样本拒绝
- 公开出牌历史约束近期已知牌，且约束位置不读取真实隐藏牌名
- 初始少量采样、低分差时逐批增加的自适应搜索
- DAgger 注释模式、教师分差/采样数记录、高置信缓存过滤
- 旧缓存按比例回放、冻结策略头训练和结构化模型集成对照

最终低预算配置使用 3 个候选、每个候选 2 次隐藏状态采样和 2 步 rollout。两批互不重叠
的随机官方模组组合、座位互换评估共 400 局，对启发式为 314 胜、78 负、8 平，得分率
79.5%，95% 区间 75.60% 至 83.40%；循环恢复和强制兜底均为 0。同一批后 200 局的
无搜索学生为 60.0%。搜索教师已跨过当前启发式 75% 门槛，瓶颈转为学生表达、标签
可学习性、在线延迟和 belief 安全审计。下一阶段优先：

1. 审计并显式建模公开历史所蕴含的牌区转移与私有引擎追踪器，消除剩余 belief 矛盾。
2. 扩展结构化特征中的长期效果归属、伤害/回复预测分解和卡牌实例生命周期。
3. 用稳定搜索轨迹重新蒸馏学生，并保留通用回放防止策略遗忘；专用纠错头仅作为对照。
4. 通过历史冠军、模组最差分位和真人诊断局验证，不把“克制当前启发式”当作上线标准。

## 数据使用

### 自我对局

当前最可靠。轨迹包含决策前公开观测、完整合法动作和选中动作，可直接训练。

### 旧回放

可用于：

- 胜负、回合数、模组与牌组分布
- 打牌和结束回合频率
- 评估训练环境的总体分布是否接近玩家

通常不可直接用于严格行为克隆，因为没有当时的完整合法动作集合，且部分长回放会
压缩状态。使用 `python -m gtn_ai.replay_audit FILE` 逐个审计。

### 新玩家数据

未来可以在服务端只保存脱敏的 AI 决策快照。训练前按账号或对局划分训练/验证集，
防止同一玩家与同一牌局同时出现在两边。

## 评估指标

- 对随机、启发式、当前线上模型和历史模型的成对胜率
- 95% 置信区间和先后手差异
- 每个官方模组组合/组合簇的最差分位胜率
- 非法动作率，目标必须为 0
- 推理 P50/P95/P99 延迟和超时回退率
- 截断对局率、平均回合数和动作数
- 离线回合超时保险触发次数（`loop_recoveries`）
- 规则更新后的回归用例通过率

不要只用训练 loss 或总体平均胜率决定上线。

离线策略没有真实思考时间，可能在“打开选择窗口、取消、再次打开”之间循环，或在一
回合内无限产生新牌。自我对局在同一信息集重复超过阈值，或单回合决策数超过预算后，
模拟线上倒计时处理余下窗口并结束回合。它记录 `loop_recoveries` 和
`forced_fallback_actions`；被强制的动作不会作为训练示范。强模型评估应要求这两个
指标接近 0。
## 上下文牌值

下一代结构化策略可启用 `docs/CONTEXTUAL_CARD_VALUE.md` 中仅使用公开信息的牌实例与
牌组上下文表示。先用 `--contextual-value-features` 重建广泛缓存，以当前结构化冠军参数
初始化，再使用搜索分歧和真人纠正微调；通过独立评估后才能替换线上模型。

当前已完成双编码保守修正器：基础模型的动作分数保持冻结，上下文编码只允许一个
零初始化的小网络在基础策略 top-k 内提出修正。12,233 条搜索标签训练出的 v2 在验证集
将保守目标命中率由 71.78% 提到 72.19%；对启发式的同种子 80 局得分与安全基础策略
同为 59.375%，直接交手为 41 胜、38 负、1 平。结果说明信息通道可用且未测得退化，
但不足以替换线上 Phelren。下一轮不继续反复拟合同一批标签，应从真人对局提取独立
局面，用更高预算搜索重标，并单独覆盖资源供给、装备指向、临时标签与多回合计划。

真人困难样本闭环现已打通：延迟标记会覆盖标记前 2 步，高预算 belief 搜索负责判断
是否真正需要纠错；筛选后按完整会话和模组组合分层切分，训练与验证不会出现同局状态
泄漏；纠错、人工复核与一致锚点具有不同样本权重，权重会进入缓存、训练损失和门控阈值
评估。首轮只有 17 个训练状态和 4 个独立验证状态，只证明流程可用。达到可训练规模前
应继续收集，目标至少为 2,000 至 5,000 个通过一致性校验的高价值状态，并让不同模组
组合、资源规划和牌实例特殊效果都有独立验证覆盖。
